# Via ↔ Estate CRM — сохранённый отключённый модуль

Дата актуализации: 22 сентября 2026 года.

## Текущее решение для Delmar

Via была подключена и позволяла просматривать внешний каталог, импортировать отдельные объекты и создавать Via-подборки. После загрузки рабочей базы агентства внешний каталог стал дублировать объекты CRM, поэтому администратор выключил интеграцию штатным серверным переключателем.

При `enabled = false` CRM не запрашивает каталог Via, не разрешает новые импорты и подборки Via и отвергает входящие события до проверки и сохранения. Вкладка Via в каталоге скрыта. Подключение и зашифрованный credential сохранены для обратимого включения; ранее импортированные объекты, их фотографии, изменения и CRM-подборки не удаляются. Рабочий клиентский канал Delmar — собственная публичная ссылка CRM.

Ниже сохранён технический контракт на случай будущего повторного включения. Он не описывает активный пользовательский сценарий Delmar.

## Product boundary

- Estate CRM и Via остаются самостоятельными продуктами. Связка выключена до явного подключения.
- Существующий CRM `ADMIN` подключает, включает и выключает модуль. Новая роль «суперадминистратор» не вводится.
- CRM владеет сделкой, контактом, фактом отправки подборки и своей историей. Via владеет публичным каталогом, подборкой в Mini App, Telegram-сессией и текущей доступностью своих объектов.
- CRM запрашивает доступный каталог Via на лету и передаёт выбранные Via external IDs. Массового автоматического копирования объектов или клиентов нет.
- Объекты CRM, которые понадобятся в Via, позже публикуются отдельным явным действием. Удаление из CRM не удаляет автоматически копию Via.
- Via возвращает в CRM события просмотра, заявки и самари сессии. CRM связывает событие со сделкой через непрозрачный контекст подборки; автоматического объединения людей по имени или Telegram username нет. Полный текст беседы не передаётся и не хранится в v1.

## Server-to-server contract v1

Подпись обеих сторон: `HMAC-SHA256(sharedCredential)` от строк, разделённых `\n`: timestamp, connectionId, uppercase method, pathname+search, SHA-256 исходного тела запроса в hex. Итог — base64url в `X-Integration-Signature`; также нужны `X-Integration-Connection` и `X-Integration-Timestamp`. Приём допускает ±5 минут, уникальный eventId обеспечивает идемпотентность повторной доставки.

CRM public Fastify API живёт от корня API-домена, **без `/api`**:

- `POST /integrations/via/pairing/claim`: Via подтверждает одноразовый код, получает `connectionId`, `sharedCredential` и `eventEndpoint`. Только этот серверный ответ содержит credential; браузер никогда его не получает.
- `POST /integrations/via/events`: подписанное событие Via. Event ID уникален в пределах организации/провайдера. События с contextId связываются с Via-подборкой, сделкой и контактом.

Первый реально подготовленный входящий тип — `mini_app_lead.created`. Via отправляет `eventId`, `connectionId`, `viaTenant`, `occurredAt`, `type`, идентификатор заявки и, если клиент пришёл по ссылке CRM, `selectionId`, `externalSelectionId`, `crmContextId`. CRM проверяет все три идентификатора подборки и записывает заявку в историю той сделки/контакта. Без контекста событие остаётся в журнале интеграции для ручного разбора; автоматического объединения контактов по имени или Telegram username нет.

CRM обращается к Via по фиксированному `VIA_API_BASE_URL`:

- `GET /api/integrations/estate/v1/properties` — страницы доступного каталога;
- `POST /api/integrations/estate/v1/selections` — до 10 Via IDs, без частичного принятия по умолчанию; Via возвращает Mini App share URL;
- `POST /api/integrations/estate/v1/selections/:selectionId/revoke` — ручной отзыв ссылки.

Публичная ссылка не содержит CRM ID сделки/контакта. Via показывает актуальные данные и не показывает отозванные подборки.

## CRM configuration (variable names only)

- `VIA_API_BASE_URL` — проверенный серверный HTTPS origin Via; значение из pairing claim не используется как HTTP target.
- `VIA_TENANT` — ожидаемый Via tenant клиента.
- `VIA_CREDENTIAL_ENCRYPTION_KEY` — случайный 32-байтный ключ в base64url для шифрования shared credential в CRM PostgreSQL. Это ключ развёртывания, не ключ клиента и не поле интерфейса.
- `API_PUBLIC_URL` — существующий публичный origin CRM API, необходимый для eventEndpoint.

Без этих настроек CRM отвечает `via_not_configured` и не выдаёт код подключения. Секреты не сохраняются в Git и не выводятся в UI.

## Условие повторного включения

Повторное включение — отдельное продуктовое решение, а не часть завершения текущей CRM. Перед ним нужно подтвердить, что внешний каталог снова нужен и не создаёт дубли, затем проверить роли `ADMIN`/`LEAD`/`MANAGER`, одноразовость pairing-кода, подписанный каталог, импорт, создание/отзыв ссылки, идемпотентность `eventId` и маршрут сделка CRM → Mini App Via → история сделки. До такого решения интеграция Delmar остаётся выключенной.
